# 设计（2.0）

## 目标

在不降低证据质量的前提下（同样的检索通道、详情增强池、期刊质量与反馈检索），让一次研究的耗时逼近理论下限：

```
耗时下限 ≈ 必需请求数 × 请求间隔 + 依赖阶段数 × 单次延迟
```

请求间隔由知网可容忍的频率决定（默认 500 ms），不是程序能消除的成本；程序能做的是：让间隔成为唯一的等待、减少必需请求数、去掉所有非网络开销。

## 结构

| 文件 | 职责 |
| --- | --- |
| `limiter.go` | 唯一节流点：按间隔发起、多请求在途、频控退避、人工验证时整体暂停 |
| `site.go` | 知网交互：捕获真实检索模板、列表/详情/期刊读取、渲染回退、人工验证、阅读 |
| `research.go` | 检索流水线：并发轮次 → 动态详情池 → 反馈 → 重排；`parallel` 工作池 |
| `jobs.go` | 异步任务、预算、长轮询、人工等待计时、检查点 |
| `store.go` | 内存数据 + 后台原子 JSON 快照 + 目录锁 |
| `parse.go` / `rank.go` / `query.go` | 页面解析、相关性与质量评分、查询规划与布尔编译 |
| `app.go` / `server.go` | 工具实现与 MCP 注册 |
| `download.go` / `documents.go` / `links.go` / `citations.go` | 下载、正文缓存、题名链接、引文格式 |

## 关键规则

- 所有请求经过 `Site.do`：先扣任务预算，再取限速槽位。并发不会提高知网看到的请求速率。
- 流水线只在真实依赖处等待：列表 → 详情池（需要初排）→ 反馈（需要已增强论文的关键词）→ 反馈增强。
- 任一请求遇到验证码或登录：限速器暂停全部新请求，弹出原页面；页面不再显示验证后自动恢复。并发撞上同一验证的请求比较验证轮次后直接重试，不重复弹窗。
- 致命错误（取消、浏览器断开、频控、站点故障）停止整批；单篇失败只记录在该记录上。预算用尽时停止派发新工作，但已发出的请求照常落地，`continue` 时不会重复请求。
- 所有阶段幂等：详情 30 天内、期刊 7 天内（无标签 1 天）不重复请求，因此继续、重跑、批量题录都只为缺失证据付费。
- 下载在点击前登记；结果未知时不再点击，需要显式 `retry=true`。
- 身份合并只依据知网标识、DOI 或完整书目；同题名不同作者保持独立。列表数据不覆盖详情页已确认的值。

## 取舍

- 放弃 bbolt 与不可变修订快照：检索结果保存为固定条目列表，题录读取最新值。换来零同步落盘与更少的状态。
- 放弃多浏览器身份、持久排除规则、断路器与传输日志：分别由单一身份、取消任务、`recover` 与“点击前登记 + 不重放”替代。
- 站点细节（检索模板捕获、QueryJson 结构、选择器、验证码识别脚本、解析规则）基于对真实页面的观察，不凭猜测编写。
